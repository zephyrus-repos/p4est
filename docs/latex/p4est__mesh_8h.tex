\doxysubsection{Detailed Description}
Forest topology in a conventional mesh format. 

A typical workflow starts with \mbox{\hyperlink{p4est__mesh_8h_a6ba36fa1d0d9ab9528ac710fac4dfe96}{p4est\+\_\+mesh\+\_\+params\+\_\+init}} to initialize a \mbox{\hyperlink{structp4est__mesh__params__t}{p4est\+\_\+mesh\+\_\+params\+\_\+t}}, followed by eventual user-\/dependent changes to the parameters.

Next a \mbox{\hyperlink{structp4est__mesh__t}{p4est\+\_\+mesh\+\_\+t}} is created with \mbox{\hyperlink{p4est__mesh_8h_a663b5101edeb5674d66a7c3692d6661a}{p4est\+\_\+mesh\+\_\+new\+\_\+params}}.

Now, the user can create a \mbox{\hyperlink{structp4est__mesh__face__neighbor__t}{p4est\+\_\+mesh\+\_\+face\+\_\+neighbor\+\_\+t}} with \mbox{\hyperlink{p4est__mesh_8h_aa4eb3c343c59cf07e06609cc802d740b}{p4est\+\_\+mesh\+\_\+face\+\_\+neighbor\+\_\+init}} and loop over a quadrants face neighbors by repeated calls to \mbox{\hyperlink{p4est__mesh_8h_a12106f289cddb28040d9c08a7d06634c}{p4est\+\_\+mesh\+\_\+face\+\_\+neighbor\+\_\+next}}.

Once done, the mesh has to be destroyed with \mbox{\hyperlink{p4est__mesh_8h_aa6fbf24e6d7bd96e9276752bef86f3a3}{p4est\+\_\+mesh\+\_\+destroy}}.
