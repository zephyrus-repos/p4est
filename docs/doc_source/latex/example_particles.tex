We include an example to track particles with a dynamic mesh.

The mesh elements are refined such that the number of particles per element stays limited to a configurable number. While the particles move in space, they also move between elements, which means that they may move between processes. We reassign particles to their holding elements in every time step and then repartition the mesh to maintain load balance, where we transfer the particles to new processes together with the holding elements.

We provide both a 2D version in \mbox{\hyperlink{particles_2particles2_8c-example}{particles/particles2.\+c}} and a 3D version in \mbox{\hyperlink{particles_2particles3_8c-example}{particles/particles3.\+c}}.\hypertarget{example_particles_autotoc_md8}{}\doxysubsection{Searching the proper element for each particle}\label{example_particles_autotoc_md8}
At any time step, any particle may make an arbitrary move through space. This often moves it out of its original holding element, and we need to find a new one. This new element may be on the same or a remote process. This example is a demo for a scalable procedure to identify it. The method works for arbitrary moves and is {\itshape not} restricted to nearest neighbor elements. In consequence, we do not rely on the \mbox{\hyperlink{structp4est__ghost}{p4est\+\_\+ghost}} algorithm but on remote and local recursive searches.\hypertarget{example_particles_autotoc_md9}{}\doxysubsubsection{Searching the process responsible for each particle}\label{example_particles_autotoc_md9}
We proceed in several stages. First, we determine the process that owns the element that the particle has moved into. We can do this in \mbox{\hyperlink{structp4est}{p4est}} {\itshape without} knowing about any local or remote elements, since the shape of the partition boundaries is encoded internally using a minimal scheme. The function to determine the process association is \mbox{\hyperlink{p4est__search_8h_ac1e3c141fb8e18837819b4b3ab35e4ad}{p4est\+\_\+search\+\_\+partition}}. It expects the user to provide a callback to indicate whether a point matches a given search element. This search element is not necessarily one of the mesh, but may be a virtual ancestor of any local or remote element, and is generated temporarily by the search recursion. The callback is informed with the current range of suspected processes as a convenience. The point is dropped if the range becomes empty, and the recursion terminates if the range shrinks to one process.\hypertarget{example_particles_autotoc_md10}{}\doxysubsubsection{Transfering particles to their elements}\label{example_particles_autotoc_md10}
In this example, if a particle changes process we send it there. Thus every process sends one message per receiver process containing all particles leaving towards it. Since the receivers do not know a priori which processes send to it, we explicitly reverse the communication pattern using the {\ttfamily sc\+\_\+notify} functionality of the sc library (see there). Once the notification algorithm returns, we have a list of sender and receiver pairs, which we pass to asynchronous MPI point-\/to-\/point communication calls.\hypertarget{example_particles_autotoc_md11}{}\doxysubsubsection{Searching the element responsible for each local particle}\label{example_particles_autotoc_md11}
Some particles stay on the same process, and those that don\textquotesingle{}t are sent away. Conversely, new particles are received that have left their previous remote process. This means that at this point, every particle is properly assigned to the process. It remains to find the local element that should be holding each one, which we accomplish by calling \mbox{\hyperlink{p4est__search_8h_a08966f233b715e731217a2c2d288bbeb}{p4est\+\_\+search\+\_\+local}}. It expects a callback similar to that of the partition search. The recursion terminates at the proper element for each particle.\hypertarget{example_particles_autotoc_md12}{}\doxysubsection{Remeshing and particle transfer}\label{example_particles_autotoc_md12}
After the particles have moved between elements, most elements will have gained or lost some. We should refine elements with increased particle density and coarsen those where the particles have thinned. To do this, we employ the classic \mbox{\hyperlink{structp4est}{p4est}} mesh adaptation mechanism and then retransfer the particles along with the updated partition. Thus, particles move between processes a second time.\hypertarget{example_particles_autotoc_md13}{}\doxysubsubsection{Adapting and repartitioning the mesh}\label{example_particles_autotoc_md13}
Given the current mesh that was used to time step the particles, we have now redistributed the particles according to their move through space, and possibly transferred them from a different process. The particles have been newly reassigned to the process local elements. We are left with the following challenges\+:


\begin{DoxyItemize}
\item Some elements hold much less or much more particles than desired.
\item The number of particles per process has become imbalanced.
\end{DoxyItemize}

We solve the first issue by adapting the mesh using the functions \mbox{\hyperlink{p4est__extended_8h_aad32df9df3630b6bac05e7366a5f1e46}{p4est\+\_\+refine\+\_\+ext}} and \mbox{\hyperlink{p4est__extended_8h_a06630b99f70cb85c73452640e8b4d54e}{p4est\+\_\+coarsen\+\_\+ext}} non-\/recursively. Optionally, we call \mbox{\hyperlink{p4est__extended_8h_a666a197be8d6d83c08cc14bfdc8565ed}{p4est\+\_\+balance\+\_\+ext}} to smooth the refinement pattern. These calls produce a mesh within the same partition boundaries, but possibly replacing a parent element with its children or vice versa. Using the \mbox{\hyperlink{p4est__extended_8h_a3183ffccd96efb695bc0b58ce6010ebd}{p4est\+\_\+replace\+\_\+t}} callback, we reassign the particles to the parent or the proper child, respectively, during the adaptation.

To solve the second problem, we \mbox{\hyperlink{p4est_8h_a808053321e785b3aba01aaa63f68517d}{p4est\+\_\+copy}} the mesh first and then \mbox{\hyperlink{p4est_8h_a54c1f4e6bc35c181952371a8046523aa}{p4est\+\_\+partition}} it using a \mbox{\hyperlink{p4est_8h_aa03358f1326e23d122ef1b155705fd4d}{p4est\+\_\+weight\+\_\+t}} function that takes into account the number of particles per element.\hypertarget{example_particles_autotoc_md14}{}\doxysubsubsection{Transfering particles on repartitioning}\label{example_particles_autotoc_md14}
We have kept the original refined mesh holding the particles and made a repartitioned mesh that is properly load balanced but still missing the particles. We use the \mbox{\hyperlink{p4est__communication_8h_ace044f4c221f25afbb9a198ff24b676a}{p4est\+\_\+transfer\+\_\+custom}} functionality to message the particles to the new process partition. The element association need not be recomputed, since the global refinement structure is left unchanged by repartitioning. At this point, we delete the old mesh and are ready for the next time step.
