An overview of the forest of octrees creation and manipulation.\hypertarget{forest_autotoc_md21}{}\doxysubsection{Introduction}\label{forest_autotoc_md21}
The forest data structure (cf. \mbox{\hyperlink{p4est_8h_abbf85f084ef575fb279717eba3aba29c}{p4est\+\_\+t}} (2D), \mbox{\hyperlink{p8est_8h_a65f9b454e1c28c2c9f60ab4a967126af}{p8est\+\_\+t}} (3D)) encodes the mesh topology as a forest of quadtrees (2D) or octrees (3D). The forest can be created given a connectivity (cf. the \mbox{\hyperlink{connectivity}{connectivity page}}). In contrast to the connectivity data structure, the forest data structure is distributed in memory when MPI is activated, i.\+e. the forest data structure only stores leaves that are processor-\/local according to the parallel mesh partition. This page provides an overview of the typical workflow in \mbox{\hyperlink{structp4est}{p4est}} to create and manipulate such a forest to represent the desired mesh topology.\hypertarget{forest_autotoc_md22}{}\doxysubsection{Forest creation}\label{forest_autotoc_md22}
A fundamental step in a typical workflow with \mbox{\hyperlink{structp4est}{p4est}} is to create a forest of quadtrees or octrees. The \mbox{\hyperlink{structp4est}{p4est}} library offers the functions \mbox{\hyperlink{p4est_8h_ac10dc6f325322ad6af793c5b6acbf4c2}{p4est\+\_\+new}} (2D), \mbox{\hyperlink{p8est_8h_a00b641bbd54c6cbb3d5b938bf2ded273}{p8est\+\_\+new}} (3D) and \mbox{\hyperlink{p4est__extended_8h_ac11cf572e8ac72c4beb78465f98b63f3}{p4est\+\_\+new\+\_\+ext}} (2D), \mbox{\hyperlink{p8est__extended_8h_a93da626bf1a48ce5030e80021b814e25}{p8est\+\_\+new\+\_\+ext}} (3D) (versions with additional parameters) to create such a forest.

{\bfseries{mpicomm}} is an MPI communicator (cf. \mbox{\hyperlink{simple_2simple2_8c-example}{simple/simple2.\+c}} for a usage example).

The highest occurring level of refinement is specified by the {\bfseries{level}} parameter. If it is zero or negative, there will be no refinement beyond the coarse mesh connectivity at this point.

We provide an optional callback mechanism (cf. {\bfseries{my\+\_\+quadrant\+\_\+init}} above) to initialize the user data that we allocate inside each forest leaf.

The {\bfseries{user\+\_\+pointer}} is assigned to the member of the same name in the created {\bfseries{forest}} (before the init callback function is called the first time). This is a way to keep the application state referenced in a forest object.

The resulting {\bfseries{forest}} object in the above example represents a uniform mesh (with the coarse mesh topolgy as encoded in the passed {\bfseries{connectivity}}) refined to the specified level. It is also possible to create a partition-\/dependent mesh by changing the two parameters set to 0 and 1 in the example above. However, for maximal reproducibility, we recommend to create a partition-\/independent mesh.

There are two types of forest manipulation. The first is to manipulate the mesh that the forest represents and the second is to the manipulate the parallel partition of the forest, i.\+e. the parallel distribution of the leaves. All forest manipulation functions in \mbox{\hyperlink{structp4est}{p4est}} manipulate either the mesh or the partition but not both. This means that the functions for changing the refinement structure do not involve MPI communication.

All forest manipulation functions are collective over the MPI communicator passed during the forest creation.\hypertarget{forest_autotoc_md24}{}\doxysubsubsection{Functions to manipulate forest\textquotesingle{}s refinement structure}\label{forest_autotoc_md24}

\begin{DoxyItemize}
\item \mbox{\hyperlink{p4est_8h_a1a31375edfa42b5609e7656233c32cca}{p4est\+\_\+refine}} Refinement of specific hypercubes given a refinement criterion, i.\+e. a user-\/defined callback function. While it is possible to enable recursive refinement, in practice we set it to non-\/recursive and loop around the function. This has the advantage that we can repartition in parallel after every iteration.
\item \mbox{\hyperlink{p4est_8h_ad250f4765d9778ec3940e9fabea7c853}{p4est\+\_\+coarsen}} Coarsen a family of hypercubes given a coarsening criterion, i.\+e. a user-\/defined callback function. This function is partition-\/dependent if families of leaves are split across processes. Partition-\/independent forests created using \mbox{\hyperlink{p4est_8h_ac10dc6f325322ad6af793c5b6acbf4c2}{p4est\+\_\+new}} or \mbox{\hyperlink{p4est__extended_8h_ac11cf572e8ac72c4beb78465f98b63f3}{p4est\+\_\+new\+\_\+ext}} as described above do not split families among proccesses. In the case that the forest\textquotesingle{}s partition is adjusted, the last call of \mbox{\hyperlink{p4est_8h_a54c1f4e6bc35c181952371a8046523aa}{p4est\+\_\+partition}} or \mbox{\hyperlink{p4est__extended_8h_a124f2669c375fa66dc746be591ca2404}{p4est\+\_\+partition\+\_\+ext}} must be with allow\+\_\+for\+\_\+coarsening activated (cf. the next section) to ensure partition-\/independent coarsening results.
\item \mbox{\hyperlink{p4est_8h_a6b603736cf5007b14755197a9c179a85}{p4est\+\_\+balance}} Ensure a 2\+:1 balance of the size differences of neighboring elements in a forest by refining mesh elements. This is accomplished by adding some more refinement where needed.
\end{DoxyItemize}

For all three ways of manipulating the forest\textquotesingle{}s refinement structure the user may pass a \mbox{\hyperlink{p4est_8h_a33d436b39a1f58fa87c265a60d2d2be3}{callback}} to initialize the user data of the newly created leaves.

Except of the mentioned special requirements for \mbox{\hyperlink{p4est_8h_ad250f4765d9778ec3940e9fabea7c853}{p4est\+\_\+coarsen}} all refinement structure manipulating functions are independent of the forest\textquotesingle{}s partition.

All of the listed functions have a version with extended options declared in \mbox{\hyperlink{p4est__extended_8h}{p4est\+\_\+extended.\+h}} (2D) and \mbox{\hyperlink{p8est__extended_8h}{p8est\+\_\+extended.\+h}} (3D).\hypertarget{forest_autotoc_md25}{}\doxysubsubsection{Function to manipulate the forest\textquotesingle{}s partition}\label{forest_autotoc_md25}
The forest\textquotesingle{}s partition is a parallel, disjoint and linear subdivision of the forest\textquotesingle{}s leaves among the MPI processes. The partition is computed using the Morton curve as space-\/filling curve.

The functions \mbox{\hyperlink{p4est_8h_ac10dc6f325322ad6af793c5b6acbf4c2}{p4est\+\_\+new}} and \mbox{\hyperlink{p4est__extended_8h_ac11cf572e8ac72c4beb78465f98b63f3}{p4est\+\_\+new\+\_\+ext}} create a uniformly partitioned forest with respect to the leaf count. However, after manipulating the forest\textquotesingle{}s refinement structure, the partition may no longer be uniform. Another reason for manipulating the partition is that the application may desire to partition the leaves according to the work associated with them instead of the leaf count. Manipulating the partition incurs MPI communication since the leaves and their data are shipped.


\begin{DoxyItemize}
\item \mbox{\hyperlink{p4est_8h_a54c1f4e6bc35c181952371a8046523aa}{p4est\+\_\+partition}} Partition the forest in parallel, equally with respect to the leaf count or according to a given user-\/defined weight per leaf. The parameter {\bfseries{allow\+\_\+for\+\_\+coarsening}} can be used to ensure that families of leaves are assigned to the same process -- cf. \mbox{\hyperlink{p4est_8h_ad250f4765d9778ec3940e9fabea7c853}{p4est\+\_\+coarsen}}.
