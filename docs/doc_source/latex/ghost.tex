An overview of the ghost layer functionalities.\hypertarget{ghost_autotoc_md27}{}\doxysubsection{The basic idea and definition}\label{ghost_autotoc_md27}
Mesh-\/based computations may require access to neighboring elements. An example of such a computation using a ghost layer can be found in \mbox{\hyperlink{steps_2p4est_step3_8c-example}{steps/p4est\+\_\+step3.\+c}} (2D) and \mbox{\hyperlink{steps_2p8est_step3_8c-example}{steps/p8est\+\_\+step3.\+c}} (3D) -- a simple parallel advection solver. For parallel computations, we we need to ensure that neighboring mesh elements, which are not local to the current process, become accessible locally. The need of process-\/neighboring mesh elements leads to the definition of the ghost (a.\+k.\+a. halo) layer\+: The ghost layer is the set of all remote, i.\+e. non-\/local, mesh elements that are adjacent to the process-\/local mesh elements. This data structure is ideally suited to establish the communication pattern between mesh-\/adjacent parallel processes. The ghost layer contains all information required to determine all sender-\/receiver pairs without additional MPI communication. The pattern is necessarily symmetric\+: Each sender of a pair is also a receiver and vice versa.\hypertarget{ghost_autotoc_md28}{}\doxysubsection{Constructing the ghost layer}\label{ghost_autotoc_md28}
{\bfseries{\mbox{\hyperlink{structp4est}{p4est}}}} provides the functions \mbox{\hyperlink{p4est__ghost_8h_a34a0bfb7169437f6fc2382a67c47e89d}{p4est\+\_\+ghost\+\_\+new}} (2D), \mbox{\hyperlink{p8est__ghost_8h_a4767b342e1f1e6f0efe4fa9eca702a72}{p8est\+\_\+ghost\+\_\+new}} (3D) to construct a ghost layer. A ghost layer can be constructed from a valid {\bfseries{input\+\_\+p4est}} (cf. \mbox{\hyperlink{p4est_8h_abbf85f084ef575fb279717eba3aba29c}{p4est\+\_\+t}} (2D), \mbox{\hyperlink{p8est_8h_a65f9b454e1c28c2c9f60ab4a967126af}{p8est\+\_\+t}} (3D) and \mbox{\hyperlink{p4est__algorithms_8h_a1f8490aec3259f0f537cdf6b0473cf8c}{p4est\+\_\+is\+\_\+valid}} (2D), \mbox{\hyperlink{p8est__algorithms_8h_ad964a86bf6f8dfd48ec03787b750abd7}{p8est\+\_\+is\+\_\+valid}} (3D)). The forest does not need to be 2\+:1 balanced.

The second and last required parameter to construct a ghost layer is a {\bfseries{btype}} (cf. \mbox{\hyperlink{p4est__connectivity_8h_adc5f6166fc408c325589ce3e620552ca}{p4est\+\_\+connect\+\_\+type\+\_\+t}} (2D), \mbox{\hyperlink{p8est__connectivity_8h_aaa5a9d47d1b169507e1095783ab89be1}{p8est\+\_\+connect\+\_\+type\+\_\+t}} (3D)) that specifies if the ghost layer should collect face adjacency, face and edge adjacency in 3D, or full adjacency including corner neighbors.

Ghost layer construction in 2D\+: \begin{quote}
{\ttfamily ghost = p4est\+\_\+ghost\+\_\+new (input\+\_\+p4est, btype)} \end{quote}
The returned ghost layer object is explained in the following section.\hypertarget{ghost_autotoc_md29}{}\doxysubsection{The ghost data structure}\label{ghost_autotoc_md29}
The ghost layer object (cf. \mbox{\hyperlink{p4est__ghost_8h_aaa1000659b80aeb802788aac34dcbf5c}{p4est\+\_\+ghost\+\_\+t}} (2D), \mbox{\hyperlink{p8est__ghost_8h_a01f7ba9154de22adb8e8f8c342d697ba}{p8est\+\_\+ghost\+\_\+t}} (3D)) can be queried and searched without accessing the original {\bfseries{input\+\_\+p4est}}. It is read-\/only immutable and must be destroyed when no longer needed (cf. \mbox{\hyperlink{p4est__ghost_8h_a4b4ae4fa996d0b8705d6267953c3e757}{p4est\+\_\+ghost\+\_\+destroy}} (2D), \mbox{\hyperlink{p8est__ghost_8h_a09828751923b505ed8faf51e2882f003}{p8est\+\_\+ghost\+\_\+destroy}} (3D)).\hypertarget{ghost_autotoc_md30}{}\doxysubsubsection{Elements of the ghost layer}\label{ghost_autotoc_md30}
The ghost layer is a public struct with documented entries, most of them arrays. The \mbox{\hyperlink{p4est__ghost_8h_aaa1000659b80aeb802788aac34dcbf5c}{2D}} and \mbox{\hyperlink{p8est__ghost_8h_a01f7ba9154de22adb8e8f8c342d697ba}{3D}} declarations are structurally identical\+: Linear tree storage is dimension independent, and ghost elements are ordered ascending just as mesh elements. We may index into the element storage by window start and offset indices. We may also use binary search in the linear order to find ghost elements.

The elements of the ghost layer start with the \mbox{\hyperlink{structp4est__ghost_af58ab604831865823b378ba79089a1ec}{mpisize}} and \mbox{\hyperlink{structp4est__ghost_a54a38e31c829e101c916765ac82a4a6f}{num\+\_\+trees}}. They store the number of MPI ranks and the number of trees of the ghost layer. Both elements are as in the \mbox{\hyperlink{group__p4est}{p4est}} that was used to construct the ghost layer.

The array \mbox{\hyperlink{structp4est__ghost_a06a0c2dfa2f05929d58ed85f0117228c}{ghosts}} stores the ghost elements that form the ghost layer of the process-\/local elements. The \mbox{\hyperlink{p4est_8h_af07461000cd68b5cd5e38b2e66b7f67b}{quadrants}} in the \mbox{\hyperlink{structp4est__ghost_a06a0c2dfa2f05929d58ed85f0117228c}{ghosts}} array store their tree index and the local number in the owner\textquotesingle{}s numbering in \mbox{\hyperlink{unionp4est__quadrant_1_1p4est__quadrant__data_ac515f7cf5f7e1ba9772ee185f3ad98f0}{piggy3}}. The \mbox{\hyperlink{structp4est__ghost_a06a0c2dfa2f05929d58ed85f0117228c}{ghosts}} array is windowed by the two arrays \mbox{\hyperlink{structp4est__ghost_ab6c23fe9fab99f812d40b24ff9afd7c1}{tree\+\_\+offsets}} and \mbox{\hyperlink{structp4est__ghost_a87fb2e3a4a30c06e09566ff65a14b12d}{proc\+\_\+offsets}}. Therefore, the MPI rank and the tree number of each element in \mbox{\hyperlink{structp4est__ghost_a06a0c2dfa2f05929d58ed85f0117228c}{ghosts}} can be deduced. Naturally, some trees or processes may have zero ghost elements for a given process, in which case the window has length zero.

The \mbox{\hyperlink{structp4est__ghost_a5d9a6ee5863c5fc3264b440849324888}{mirrors}} array stores all local quadrants that are ghosts to remote processes, sometimes called the (inside) parallel boundary elements. \mbox{\hyperlink{structp4est__ghost_a06a0c2dfa2f05929d58ed85f0117228c}{ghosts}} can be considered as the outside parallel boundary elements. One mirror quadrant may be ghost to more than one remote process. Thus, the indexing structure is slightly less direct than for \mbox{\hyperlink{structp4est__ghost_a06a0c2dfa2f05929d58ed85f0117228c}{ghosts}}\+: We have an array \mbox{\hyperlink{structp4est__ghost_ad71ab27aec27b091153a4fdc8a4515f3}{mirror\+\_\+proc\+\_\+mirrors}} that contains one set of indices into the \mbox{\hyperlink{structp4est__ghost_a5d9a6ee5863c5fc3264b440849324888}{mirrors}} for each remote process. The array \mbox{\hyperlink{structp4est__ghost_a5ab6b80790c11b4752d2ecf198954f9b}{mirror\+\_\+proc\+\_\+offsets}} indexes into these sets, which vary in length by the remote process. As for \mbox{\hyperlink{structp4est__ghost_a06a0c2dfa2f05929d58ed85f0117228c}{ghosts}}, we have for \mbox{\hyperlink{structp4est__ghost_a5d9a6ee5863c5fc3264b440849324888}{mirrors}} also an array with tree offsets, namely the array \mbox{\hyperlink{structp4est__ghost_a46788f88d0ca86e8361c821c54386dd6}{mirror\+\_\+tree\+\_\+offsets}}.\hypertarget{ghost_autotoc_md31}{}\doxysubsection{Find more information}\label{ghost_autotoc_md31}
