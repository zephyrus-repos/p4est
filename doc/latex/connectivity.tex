An overview of the connectivity structure.\hypertarget{connectivity_autotoc_md0}{}\doxysubsection{The basic idea and definition}\label{connectivity_autotoc_md0}
\mbox{\hyperlink{structp4est}{p4est}} leverages structured octree grids for efficient highly-\/scalable adaptive mesh refinement (AMR). At the same time \mbox{\hyperlink{structp4est}{p4est}} enables the user to represent a general and possibly non-\/squared (2D), non-\/cubic (3D) domain. This flexibility for the domain choice is achieved by using a forest of quadtrees (2D) or octrees (3D) instead of a single tree. The forest represents a coarse mesh topology where each tree is a logical hypercube. To represent a general domain, we cover the domain with a conforming mesh of (potentially mapped) squares (2D) or cubes (3D). Each square (2D) or cube (3D) represents a quadtree (2D) or octree (3D) root. These trees are connected with respect to their root\textquotesingle{}s topological entities, i.\+e. in 2D corners and faces and in 3D corners, faces and edges. This coarsest possible mesh is defined as the connectivity of a forest. It can not be changed during a simulation and in particular it can not be coarsened further.\hypertarget{connectivity_autotoc_md1}{}\doxysubsection{Guidelines for connectivity design}\label{connectivity_autotoc_md1}
Since the connectivity can not be changed during a simulation it should be designed carefully. A few guidelines (replace cube(s) by square(s) for 2D) are\+:
\begin{DoxyEnumerate}
\item Use as many cubes as needed to capture the domain\textquotesingle{}s topology (connected components, holes, tunnels, etc.).
\item Invest some more cubes to achieve an ideally uniform individual aspect ratio of each cube.
\item Invest some more cubes if the distortion in any single mapped octree appears too large.
\item Reduce the number of trees if the coarse mesh must be limited for numerical reasons.
\end{DoxyEnumerate}

We have successfully connected millions of trees. Below 100k, there is no need to even think about reducing their number if the procedure would not be obvious.\hypertarget{connectivity_autotoc_md2}{}\doxysubsection{Constructing the connectivity}\label{connectivity_autotoc_md2}
The easiest way to create a connectivity is to use one of the predefined functions in \mbox{\hyperlink{p4est__connectivity_8h}{p4est\+\_\+connectivity.\+h}} (2D) or \mbox{\hyperlink{p8est__connectivity_8h}{p8est\+\_\+connectivity.\+h}} (3D). These predefined functions {\ttfamily p4est\+\_\+connectivity\+\_\+new\+\_\+$\ast$} (2D) and {\ttfamily p8est\+\_\+connectivity\+\_\+new\+\_\+$\ast$} (3D) implement some basic connectivities like a unit square (\mbox{\hyperlink{p4est__connectivity_8h_aab03936b137ccdc4fa7520e7e017fcf0}{p4est\+\_\+connectivity\+\_\+new\+\_\+unitsquare}}) or a unit cube (\mbox{\hyperlink{p8est__connectivity_8h_a53bdb596e76c52c1e23aaecd0aacc763}{p8est\+\_\+connectivity\+\_\+new\+\_\+unitcube}}) but also more advanced connectivities like an icosahedron (\mbox{\hyperlink{p4est__connectivity_8h_a22189ecf16818e0ad94f7be8070027d1}{p4est\+\_\+connectivity\+\_\+new\+\_\+icosahedron}}) or a 3D torus (\mbox{\hyperlink{p8est__connectivity_8h_aa50117d066094039f84db7e27600d0a9}{p8est\+\_\+connectivity\+\_\+new\+\_\+torus}}).

Moreover, we want to point to the possibility of connecting topological entities inside a single tree. This means that one can create periodic connectivities, e.\+g. \mbox{\hyperlink{p4est__connectivity_8h_ae65fe72b77b6f6c6825fc33efc101dab}{p4est\+\_\+connectivity\+\_\+new\+\_\+periodic}} (2D) and \mbox{\hyperlink{p8est__connectivity_8h_a1374c4c2fc06e436e047d32c28b87288}{p8est\+\_\+connectivity\+\_\+new\+\_\+periodic}} (3D).

We also offer the functions \mbox{\hyperlink{p4est__connectivity_8h_af3521f9ecb47a49eefec6077fd97429c}{p4est\+\_\+connectivity\+\_\+read\+\_\+inp}} (2D) and \mbox{\hyperlink{p8est__connectivity_8h_a323fe9836afb429b60a8b06ff0f6c08c}{p8est\+\_\+connectivity\+\_\+read\+\_\+inp}} (3D) to read a connectivity from an Abaqus {\ttfamily .inp} file.

The user can also create a new connectivity by allocating and populating the connectivity structure using \mbox{\hyperlink{p4est__connectivity_8h_aee6fba5010f5af2b14833987b29dee23}{p4est\+\_\+connectivity\+\_\+new\+\_\+copy}} (2D) or \mbox{\hyperlink{p8est__connectivity_8h_a32ba2ce6d92b624180275f844e061a8f}{p8est\+\_\+connectivity\+\_\+new\+\_\+copy}} (3D). See the next section and \mbox{\hyperlink{p4est__connectivity_8h_a7bfc76825a73a3764b063ef476ed62f3}{p4est\+\_\+connectivity\+\_\+t}} (2D) or \mbox{\hyperlink{p8est__connectivity_8h_ae35f889062e2e420a5534facd7aaf6a0}{p8est\+\_\+connectivity\+\_\+t}} (3D) for more information on the elements of the connectivity structure.\hypertarget{connectivity_autotoc_md3}{}\doxysubsubsection{Reducing storage size on shared-\/memory nodes}\label{connectivity_autotoc_md3}
Since the connectivity must be identical on every process, it is sufficient to generate it once on every shared memory node and share its contents using MPI3 functionality. We provide the function \mbox{\hyperlink{p4est__connectivity_8h_afbf34f950b045fb2b4b29440da487660}{p4est\+\_\+connectivity\+\_\+share}} for this purpose. Prior to calling it, the user may make the connectivity available on every first rank of every shared-\/memory node, for example using \mbox{\hyperlink{p4est__connectivity_8h_ae75350b07743b53c0af735c7683660b4}{p4est\+\_\+connectivity\+\_\+bcast}} over a communicator that contains these first ranks only.

For convenience, we integrate this approach in \mbox{\hyperlink{p4est__connectivity_8h_a8368869b9ad93ec9b399ecbb2a795fb9}{p4est\+\_\+connectivity\+\_\+mission}}. It requires to input a connectivity on just the root of the world communicatior and then distributes it using MPI-\/3 shared memory. This function uses safe fallbacks when MPI-\/3 is not detected on configuration, or when we compile entirely without MPI.\hypertarget{connectivity_autotoc_md4}{}\doxysubsection{The connectivity data structure}\label{connectivity_autotoc_md4}
The connectivity data structure (cf. \mbox{\hyperlink{p4est__connectivity_8h_a7bfc76825a73a3764b063ef476ed62f3}{p4est\+\_\+connectivity\+\_\+t}} (2D), \mbox{\hyperlink{p8est__connectivity_8h_ae35f889062e2e420a5534facd7aaf6a0}{p8est\+\_\+connectivity\+\_\+t}} (3D)) is a public struct with documented entries and it is independent of the MPI rank and hence must be the same on all MPI ranks.

You may build any numbers of forests with the same connectivity object, but the connectivity object must be destroyed only after the last of the forests has been freed and the connectivity object must definitely be destroyed (\mbox{\hyperlink{p4est__connectivity_8h_a208e613cae5e1bd3baffb587387b672c}{p4est\+\_\+connectivity\+\_\+destroy}} (2D), \mbox{\hyperlink{p8est__connectivity_8h_a83dc515293fe5f7c82eade6e281a62ca}{p8est\+\_\+connectivity\+\_\+destroy}} (3D)).\hypertarget{connectivity_autotoc_md5}{}\doxysubsubsection{Elements of the connectivity}\label{connectivity_autotoc_md5}
The connectivity data structure consists of arrays and counts of different entities. In particular, the connectivity data structure contains the number of trees \mbox{\hyperlink{structp4est__connectivity_a1068e552922e0e98a1f2477020392b25}{num\+\_\+trees}} and the number of vertices \mbox{\hyperlink{structp4est__connectivity_a0894477852eb4b80afb6f90a941f4988}{num\+\_\+vertices}}. The vertices are stored in the double array \mbox{\hyperlink{structp4est__connectivity_ae955f91894a96c94bb05dceb270ce58f}{vertices}}. It is important to note that the vertices are always points in the three-\/dimensional space; even in the \mbox{\hyperlink{p4est__connectivity_8h_a7bfc76825a73a3764b063ef476ed62f3}{2D connectivity}}. The \mbox{\hyperlink{structp4est__connectivity_ae955f91894a96c94bb05dceb270ce58f}{vertices}} are used to embed each tree into the three-\/dimensional space in the array \mbox{\hyperlink{structp4est__connectivity_a9ff441d9dcadc317d5acfdfdb73b0dd5}{tree\+\_\+to\+\_\+vertex}}. This embedding is for example used for visualization (cf. \mbox{\hyperlink{p4est__vtk_8h}{p4est\+\_\+vtk.\+h}} (2D), \mbox{\hyperlink{p8est__vtk_8h}{p8est\+\_\+vtk.\+h}} (3D)) or a custom transformation from tree-\/local coordinates to a user-\/defined physical space (cf. \mbox{\hyperlink{p4est__geometry_8h_af9ba2d7b679c66899ddb82c1623e7ce4}{p4est\+\_\+geometry\+\_\+new\+\_\+connectivity}} (2D), \mbox{\hyperlink{p8est__geometry_8h_a358133eb3dada44e4f6868b6bfa93b01}{p8est\+\_\+geometry\+\_\+new\+\_\+connectivity}} (3D)). The remaining counts in the connectivity structure are the number of different topological entities that help to define the coarse mesh\+: The \mbox{\hyperlink{structp4est__connectivity_a89a2d05fa39c9174d6b93012be4aa7c2}{num\+\_\+corners}} is the number of corners that are not part of a face neighborhood (or edge neighborhood in \mbox{\hyperlink{structp8est__connectivity_a1c21655509afcffa03267f489f731609}{3D}}) but connect trees. Similarly, we have \mbox{\hyperlink{structp8est__connectivity_ab237b9a727bb52663ab58a5eeed8a439}{num\+\_\+edges}} in addition in 3D -- storing the number of edges that are not part of a face neighborhood but connect trees. Then arrays like \mbox{\hyperlink{structp4est__connectivity_abd359ad4f42fa6f3bef058c5fbdebf5a}{tree\+\_\+to\+\_\+tree}} and \mbox{\hyperlink{structp4est__connectivity_a1cdfd9e7d8bc9ccab32a2e389c2ea231}{tree\+\_\+to\+\_\+face}} encode the inter-\/tree connectivity information. For more information of the encoding in these arrays and the other arrays see the documentation of \mbox{\hyperlink{p4est__connectivity_8h_a7bfc76825a73a3764b063ef476ed62f3}{p4est\+\_\+connectivity\+\_\+t}} (2D) and \mbox{\hyperlink{p8est__connectivity_8h_ae35f889062e2e420a5534facd7aaf6a0}{p8est\+\_\+connectivity\+\_\+t}} (3D) and the documentation of the respective elements of these two structures.\hypertarget{connectivity_autotoc_md6}{}\doxysubsection{Find more information}\label{connectivity_autotoc_md6}
For information on further connectivity functionalities we refer to \mbox{\hyperlink{p4est__connectivity_8h}{p4est\+\_\+connectivity.\+h}} (2D) and \mbox{\hyperlink{p8est__connectivity_8h}{p8est\+\_\+connectivity.\+h}} (3D). In particular, you can find there functions for \mbox{\hyperlink{p4est__connectivity_8h_af8be3fd9a6c96e3e2a710f9251952cf3}{writing}} and \mbox{\hyperlink{p4est__connectivity_8h_a4d8d6cb8fd999dd939bdf1159d3e2723}{reading}} a connectivity in a \mbox{\hyperlink{structp4est}{p4est}} internal file format. There are also functions to manipulate connectivity objects, e.\+g. one can use METIS -- if it is available -- to \mbox{\hyperlink{p4est__connectivity_8h_a6fa55094144a0dc59e8dfc16cf33caf0}{reorder}} a connectivity.\hypertarget{connectivity_autotoc_md7}{}\doxysubsection{Example of connectivity usage}\label{connectivity_autotoc_md7}
