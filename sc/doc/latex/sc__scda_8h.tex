\doxysubsection{Detailed Description}
Routines for parallel I/O with the {\bfseries{scda}} format. 

\begin{DoxyWarning}{Warning}
This API will change in the next libsc version!
\end{DoxyWarning}
Functionality to write and read in parallel using a prescribed serial-\/equivalent file format called {\bfseries{scda}}.\hypertarget{sc__scda_8h_autotoc_md0}{}\doxyparagraph{General}\label{sc__scda_8h_autotoc_md0}
The {\bfseries{scda}} format is as in this \href{https://doi.org/10.48550/arXiv.2307.06789}{\texttt{ preprint}}.

However, in contrast to the preprint the API in this file provides the two functions \mbox{\hyperlink{sc__scda_8h_a14638ad9e17b15a3e449e4e10fee507c}{sc\+\_\+scda\+\_\+fopen\+\_\+write}} and \mbox{\hyperlink{sc__scda_8h_ac336fd36bcbff9f64fd23f63028b4f89}{sc\+\_\+scda\+\_\+fopen\+\_\+read}} instead of providing one opening function with a mode parameter to decide and writing and reading.

In addition, we add in this file the options structure \mbox{\hyperlink{structsc__scda__params}{sc\+\_\+scda\+\_\+params}} as parameter for opening files.

The file format includes metadata in ASCII and therefore enables the human eye to parse the file structure using a standard text editor.

The file format {\bfseries{scda}} is in particular suitable for parallel I/O and is accompanied by a convention for element-\/wise compression.

The format is designed such that the the parallel partition and in particular the process count can differ between writing and reading.

The main purpose of {\bfseries{scda}} is to enable the user to implement parallel I/O for numerical appliations, e.\+g. simulation checkpoint/restart.

We elaborate further on the workflow in \mbox{\hyperlink{scda_workflow}{Parallel I/O workflow}}.

The {\bfseries{scda}} functions do not support the deprecated configuration case of MPI being enabled but MPI I/O being disabled. The functions \mbox{\hyperlink{sc__scda_8h_a14638ad9e17b15a3e449e4e10fee507c}{sc\+\_\+scda\+\_\+fopen\+\_\+write}} and \mbox{\hyperlink{sc__scda_8h_ac336fd36bcbff9f64fd23f63028b4f89}{sc\+\_\+scda\+\_\+fopen\+\_\+read}} abort in this case. All other valid configurations are supported.\hypertarget{sc__scda_8h_autotoc_md1}{}\doxyparagraph{User Strings}\label{sc__scda_8h_autotoc_md1}
The functions

have {\bfseries{user\+\_\+string}} and {\bfseries{len}} as an argument.

The user string consisting of the two parameters {\bfseries{user\+\_\+string}} and {\bfseries{len}} is always a collective parameter.

In the case of writing these arguments have the purpose to pass the user string that is written to the file.

There are two options writing the user string to the file.


\begin{DoxyEnumerate}
\item A nul-\/terminated string {\bfseries{user\+\_\+string}}, i.\+e. a standard C string. In this case {\bfseries{len}} is set to NULL since the length of {\bfseries{user\+\_\+string}} is implicitly given by the nul-\/termination.
\item Arbitrary data for the user string including possible \textquotesingle{}\textbackslash{}0\textquotesingle{} in non-\/terminating positions. We still require nul-\/termination for safety. One needs to explicitly pass the length, i.\+e. the number of bytes excluding the nul-\/termination.
\end{DoxyEnumerate}

For both options it must be respected that the number of maximal {\bfseries{user\+\_\+string}} bytes is \mbox{\hyperlink{sc__scda_8h_a2000763de9ddb4fa54d485df7cfe9378}{SC\+\_\+\+SCDA\+\_\+\+USER\+\_\+\+STRING\+\_\+\+BYTES}} + 1 including the nul-\/termination.

In case of reading {\bfseries{user\+\_\+string}} must be at least \mbox{\hyperlink{sc__scda_8h_a2000763de9ddb4fa54d485df7cfe9378}{SC\+\_\+\+SCDA\+\_\+\+USER\+\_\+\+STRING\+\_\+\+BYTES}} + 1 bytes. On output {\bfseries{len}} is set to the number of bytes actually written to {\bfseries{user\+\_\+string}} excluding the nul-\/termination.

If it is desired to write arbitrary data without the nul-\/termination, which is required for the user string, one can write a block data section using the function \mbox{\hyperlink{sc__scda_8h_a1f2290fa5a5f963ab29290ff3fe7d506}{sc\+\_\+scda\+\_\+fwrite\+\_\+block}}.\hypertarget{sc__scda_8h_autotoc_md2}{}\doxyparagraph{Encoding}\label{sc__scda_8h_autotoc_md2}
{\bfseries{scda}} provides optional transparent, element-\/wise compression of data of file sections. The compression for writing can be enabled by passing true for {\bfseries{encode}} to one of the functions


\begin{DoxyItemize}
\item \mbox{\hyperlink{sc__scda_8h_a82eec2df05911d66d8ce1673343862b7}{sc\+\_\+scda\+\_\+fwrite\+\_\+inline}},
\item \mbox{\hyperlink{sc__scda_8h_a1f2290fa5a5f963ab29290ff3fe7d506}{sc\+\_\+scda\+\_\+fwrite\+\_\+block}},
\item \mbox{\hyperlink{sc__scda_8h_ad645fba87e9fac212c635f4c91cecec9}{sc\+\_\+scda\+\_\+fwrite\+\_\+array}} and
\item \mbox{\hyperlink{sc__scda_8h_a82171bb305fc39e606fa02f5948d27b0}{sc\+\_\+scda\+\_\+fwrite\+\_\+varray}}.
\end{DoxyItemize}

The compression on writing can be decided by the user for each file section separately. All parameters on the size of the data written to the file refer to the uncompressed data.

On reading it sufficies to pass {\bfseries{decode}} true to the function \mbox{\hyperlink{sc__scda_8h_aa7a7eddf6cf00319260e93bac577aab8}{sc\+\_\+scda\+\_\+fread\+\_\+section\+\_\+header}}. Then the file section data is decompressed if it was compressed and otherwise the file section data is read raw. Again all data sizes in reading functions refer to the uncompressed data.

If {\bfseries{decode}} is false, the data is read raw even if it was written according to the compression convention.\hypertarget{sc__scda_8h_autotoc_md3}{}\doxyparagraph{Error management}\label{sc__scda_8h_autotoc_md3}
All {\bfseries{scda}} functions that receive a file context have an output parameter called {\bfseries{errcode}}. In case of an unsuccessful function call, the respective function returns NULL instead of the file context and sets the output parameter {\bfseries{errcode}} to the respective error code. If such a case occurs, the file that is associated to the used file context is closed and the file context is deallocated.

The error code can be examined by the user using the two functions
\begin{DoxyItemize}
\item \mbox{\hyperlink{sc__scda_8h_a01762ce01ec64b560cff9ba9fbf66548}{sc\+\_\+scda\+\_\+ferror\+\_\+class}} and
\item \mbox{\hyperlink{sc__scda_8h_a1191840fde06a11537122a5701a75eef}{sc\+\_\+scda\+\_\+ferror\+\_\+string}}.
\end{DoxyItemize}

If MPI is available {\bfseries{errcode}} may encode an MPI error code. In this case the two error examination functions output the error class and error string as it would be output by the corresponding MPI functions, respectively. Without MPI it is still possible that {\bfseries{errcode}} encodes an I/O operation related error code. This case does not differ concerning the error code examiniation. Moreover, {\bfseries{errcode}} can encode an error code related to {\bfseries{scda}}, i.\+e. the I/O operations were successful but there is some violation of the {\bfseries{scda}} format, workflow or API.

For more technical details on {\bfseries{errcode}} see the documentation of \mbox{\hyperlink{sc__scda_8h_a3613f101cd3d474bae0609313c45a135}{sc\+\_\+scda\+\_\+ferror\+\_\+t}}. Furthermore, the {\bfseries{scda}} format, workflow or API errors description can be found in the documentation of \mbox{\hyperlink{sc__scda_8h_a859537bb0f5ff43711604b848a8a7477}{sc\+\_\+scda\+\_\+ret}}.
