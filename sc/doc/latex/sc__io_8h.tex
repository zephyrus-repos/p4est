\doxysubsection{Detailed Description}
Helper routines for general and parallel I/O. 

This file provides various sets of functions related to write and read data as well es to encode and decode it to certain formats.


\begin{DoxyItemize}
\item To abstract transparent writing/reading into/from files or buffers, we provide functions centered around \mbox{\hyperlink{sc__io_8h_ab691d0047bd873d576d07950b439cca9}{sc\+\_\+io\+\_\+sink\+\_\+new}} and \mbox{\hyperlink{sc__io_8h_ae61efc9bf75e5aca4877672fe9d575e0}{sc\+\_\+io\+\_\+source\+\_\+new}}.
\item To abstract parallel file I/O in a way that works both with and without MPI support, we provide \mbox{\hyperlink{sc__io_8h_aa79491ec78fabf548a23f7cebf3c6f50}{sc\+\_\+io\+\_\+open}}, \mbox{\hyperlink{sc__io_8h_a1cad9d095f810ac5cb1165b4b9818a1d}{sc\+\_\+io\+\_\+write}} and friends.
\item To write to the VTK binary compressed format, we provide suitable functions to base64 encode and zlib-\/compress as required; see \mbox{\hyperlink{sc__io_8h_afbfb10dfc461f46c52cd3837ff2e79ac}{sc\+\_\+vtk\+\_\+write\+\_\+binary}} and \mbox{\hyperlink{sc__io_8h_adef98453c04d4b59cb55afc5719c0273}{sc\+\_\+vtk\+\_\+write\+\_\+compressed}}.
\item To support self-\/contained ASCII-\/armored compression, we provide the functions \mbox{\hyperlink{sc__io_8h_a98ab4446cc9f9f90cec50e5ed04b9575}{sc\+\_\+io\+\_\+encode}}, \mbox{\hyperlink{sc__io_8h_aa398e72498b16db42b5c73a26089a036}{sc\+\_\+io\+\_\+decode\+\_\+info}} and \mbox{\hyperlink{sc__io_8h_a99317ed3eb0e67c0c8f907ad1d2f00af}{sc\+\_\+io\+\_\+decode}}. They losslessly transform a block of arbitrary data into a compressed and base64-\/encoded format and back that is unambiguously defined and human-\/friendly. 
\end{DoxyItemize}

{\footnotesize\ttfamily int sc\+\_\+io\+\_\+decode (\begin{DoxyParamCaption}\item[{\mbox{\hyperlink{sc__containers_8h_a619346753d2a15625bda06835c83e5e2}{sc\+\_\+array\+\_\+t}} $\ast$}]{data,  }\item[{\mbox{\hyperlink{sc__containers_8h_a619346753d2a15625bda06835c83e5e2}{sc\+\_\+array\+\_\+t}} $\ast$}]{out,  }\item[{size\+\_\+t}]{max\+\_\+original\+\_\+size,  }\item[{void $\ast$}]{re }\end{DoxyParamCaption})}



Decode a block of base 64 encoded compressed data. 

The base 64 data must contain two arbitrary bytes after every 76 code characters and also at the end of the last line if it is short, and then a final NUL character. This function does not require zlib but benefits for speed.

This is a two-\/stage process\+: we decode the input from base 64 first. Then we extract the 8-\/byte big-\/endian original data size, the character \textquotesingle{}z\textquotesingle{}, and execute a zlib decompression on the remaining decoded data. This function detects malformed input by erroring out.

If we should add another format in the future, the format character may be something else than \textquotesingle{}z\textquotesingle{}, as permitted by our specification. To this end, we reserve the characters A-\/C and d-\/z indefinitely.

Any error condition is indicated by a negative return value. Possible causes for error are\+:


\begin{DoxyItemize}
\item the input data string is not NUL-\/terminated
\item the first 12 characters of input do not decode properly
\item the input data is corrupt for decoding or decompression
\item the output data array has non-\/unit element size and the length of the output data is not divisible by the size
\item the output data would exceed the specified threshold
\item the output array is a view of insufficient length
\end{DoxyItemize}

We also error out if the data requires a compression dictionary, which would be a violation of above encode format specification.

The corresponding encode function is \mbox{\hyperlink{sc__io_8h_a98ab4446cc9f9f90cec50e5ed04b9575}{sc\+\_\+io\+\_\+encode}}. When passing an array as output, we resize it properly. This function cannot crash unless out of memory.

It must be in the exact format produced by \mbox{\hyperlink{sc__io_8h_a98ab4446cc9f9f90cec50e5ed04b9575}{sc\+\_\+io\+\_\+encode}}; please see documentation. Encode a block of arbitrary data, compressed, into an ASCII string. 

This is a two-\/stage process\+: zlib compress and then encode to base 64. The output is a NUL-\/terminated string of printable characters.

We first compress the data into the zlib deflate format (RFC 1951). The compressor must use no preset dictionary (this is the default). If zlib is detected on configuration, we compress with the given level. If zlib is not detected, we write data equivalent to Z\+\_\+\+NO\+\_\+\+COMPRESSION. The status of zlib detection can be queried at compile time using \#ifdef SC\+\_\+\+HAVE\+\_\+\+ZLIB or at run time using \mbox{\hyperlink{sc_8h_a13762c105b94355ab4bd34641bb5c5b5}{sc\+\_\+have\+\_\+zlib}}. Both types of result are readable by a standard zlib uncompress call.

Secondly, we process the input data size as an 8-\/byte big-\/endian number, then the letter \textquotesingle{}z\textquotesingle{}, and then the zlib compressed data, concatenated, with a base 64 encoder. We break lines after 76 code characters. Each line break consists of two configurable but arbitrary bytes. The line breaks are considered part of the output data specification. The last line is terminated with the same line break and then a NUL.

This routine can work in place or write to an output array. The corresponding decoder function is \mbox{\hyperlink{sc__io_8h_a99317ed3eb0e67c0c8f907ad1d2f00af}{sc\+\_\+io\+\_\+decode}}. This function cannot crash unless out of memory.
